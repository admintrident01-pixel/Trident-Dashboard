# Shared schedule updates

The Cloudflare Worker serves the existing static app and a read-only WebSocket endpoint at `/schedule-live`. One `ScheduleRoom` Durable Object fans out saved-change notifications to the signed-in sessions. Business values stay in the existing authenticated Python API and business register.

Configure the same high-entropy signing secret (at least 32 characters) as `SCHEDULE_LIVE_SECRET` in the existing Cloudflare Worker and Cloud Run API. Keep it in the platforms' secret stores; never in Git, a frontend build variable or a release archive. Cloud Run's existing `FRONTEND_ORIGIN` must remain the approved HTTPS dashboard origin. Preserve the existing Google Routes and email secret bindings. The current configuration creates the new SQLite Durable Object binding through migration `schedule-live-v1`; it does not migrate business records.

Only authenticated active accounts can obtain a five-minute signed connection ticket. The browser sends the ticket through the WebSocket subprotocol rather than the URL. The Worker checks its signature, expiry and exact origin. Clients cannot write through this connection. Only the API can publish signed invalidations, and it does so after a successful durable commit. Frames contain only `schedule-changed`, never booking, customer, staff or leave details. Tickets renew automatically; their maximum lifetime limits access after a session is revoked.

All schedule mutation endpoints remain administrator-only. Technicians can view the board and receive updates. Open appointment forms are independent of refreshed board data. A bounded three-way merge applies independent changes; two different edits to the same field require an explicit choice at Save. Network-uncertain writes are never blindly retried. Unfinished appointment forms are saved per user in the current tab's session storage and can be resumed after reload while that browser session remains available. They are not a server backup and are removed when session storage is cleared.

If live configuration is missing or a connection drops, visible schedule screens check automatically each second. A connected screen also checks every five seconds to recover a missed notification. Hidden pages close the live connection and re-authenticate when shown again. Dragging, selection and active writes are protected; pending invalidations wait until the gesture or write completes. A notification failure does not fail an already committed business save.

Back up and compare the authoritative live register and uploaded files around deployment. Do not deploy the patched sample-preview build or its synthetic `.dev.vars` file. Deploy from the production-safe source. Verify both WebSocket delivery and fallback refresh online after enabling both secret bindings.
