DATABASE CHOICE
The supplied backend follows the screenshot's BigQuery approach, with a single
versioned register record for this initial one-person app. Each save atomically
checks and advances the global revision in one conditional UPDATE. PDFs are
immutable private objects; their references change with the register commit.
A lost response requires refreshing Home before retrying. Failed PDF cleanup
can leave an unreferenced private object; it does not appear in the quote list.
BigQuery is an analytics database, so queries/saves may be slower than a normal
transaction database. This implementation enforces an 8 MiB register size cap.
Before wider team use or a large register, prefer a transactional database.
The database choice can still be changed before deployment; a SQLite adapter
exists only for local test verification, not Cloud Run production storage.
https://docs.cloud.google.com/bigquery/docs/best-practices-performance-compute
