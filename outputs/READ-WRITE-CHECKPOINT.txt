Read/write conflict and efficiency update, 13 November 2026 (Pacific/Auckland)
Branch: codex/Readwrite

PROBLEM
Schedule and Stock saves intermittently failed with "another version exists".
Every write checked the single global register revision, so an unrelated save
(a time sheet draft, reminder job, settings change or another page) made the
page's edit token look stale. The data being edited had not changed.

FIX
- Added scoped tokens in backend/core.py: scope_digest, state_tag, tag_matches.
- Added Application.write() in backend/app.py. It retries and rebases a save only
  when the collections that page edits are unchanged. Genuine concurrent edits
  to the same collection still return 409, so real conflicts are not overwritten.
- Added scoped ETags and POST checks for Stock, stocktake, Schedule, schedule
  notes/settings, vehicle checks/settings/order, staff setup, labour, weekly
  report, quote/workbook/time settings and the recycle bin.
- Legacy global revision tokens remain accepted for older clients.
- Appointment email saves never retry an uncertain delivery, avoiding duplicates.
- Pages auto-refresh after a genuine 409 and ask the user to press Save again.

EFFICIENCY
- backend/stock.py indexes allocations and asset-number movements once instead
  of rescanning them for every asset. balance_index() computes all product
  balances in one pass over assets and receipts.
- backend/stock_import.py reuses those indexes when exporting.
- Stock, stocktake, schedule, schedule-link and history mutations copy only the
  edited collections instead of deep-copying the whole register/workbook.
- recycle.capture() copies state only when something is actually archived.
- Stock and settings POST responses return fresh payloads, avoiding a second GET.
- Synthetic 5,000-asset stock read: about 0.32-0.44 seconds. The current local
  register is near-empty and reads in under a millisecond.
